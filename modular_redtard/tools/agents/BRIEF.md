# Памятка агенту блока

Обязательна для каждого агента, которого координатор запускает на задачу из `modular_redtard/TASKS.md`. В том же рабочем дереве одновременно работают другие агенты, поэтому правила жёсткие. Где памятка расходится с другим документом, действует она; где документ расходится с кодом — код.

## Правила

1. **Апстрим ТГ не правится никогда.** Твоё — только `modular_redtard/`, `config/redtard/`, `config/redtard_private/` и рабочая папка блока. Нужна правка апстрима — не делай её, запиши в отчёт.
2. **Только свои файлы.** Пиши в папки и файлы из «Владеет» своей задачи, чужое только читай. Общие файлы — `_module.dme`, `README.md`, `TASKS.md`, `OVERRIDES.md`, корневой `README.md` — правит только сборщик блока: нужные строки (include по порядку, имена новых файлов чисел, переопределения ТГ, заметки для README) оставь в отчёте. Папки `ported/` и `localization/strings/descriptions.txt` пишут генераторы, руками их не правят.
3. **Git только на чтение** (`status`, `diff`, `log`, `show`). Ничего, что меняет состояние: `add`, `commit`, `checkout`, `restore`, `stash`, `reset`, `submodule`. В `config/redtard_private`, `.cache` и в папках форков git не запускай вовсе: это вложенные и чужие клоны.
4. **Без `cd`.** Он сдвигает рабочую папку всей сессии и ломает fnm. Только абсолютные пути; корень — `C:\RedTardProject\tgstation-RPG` (в Bash `/c/RedTardProject/tgstation-RPG`).
5. **Не собирай и не запускай.** Ни DM, ни бандлы tgui, ни сервер, ни тесты: тулчейн один на всех. Можно Python (`py -3`), `tsc`, Biome. Собирает сборщик блока, один раз.
6. **Числа — в приватный репозиторий** (главное правило механик). Число баланса не пишется ни дефайном, ни литералом: в коде `rogue_value("имя")`, а настоящее число с описанием кладётся в `staged/<ключ задачи>/<файл чисел>.txt` рабочей папки блока (формат — как в приватных файлах `config/redtard_private/mechanics/values/`: строки `#` над `имя = число`, пустая строка между записями, время в децисекундах; в описании самого числа нет). В приватные файлы записи сводит `tools/private_config/code_numbers.py merge`, открытые (те же имена, число 10) пишет `sync` — запускает их тот, кого назвал план. Сам приватные и открытые файлы чисел не правь, если это не твоя задача. `rogue_value()` — вызов процедуры: нельзя там, где DM ждёт константу (начальное значение переменной типа, `var/const`, `var/static`, `GLOBAL_…_INIT`, метка `switch`, `#if`), — там число берут в `Initialize()` или `New()`; в горячих путях (`process`, `Life`, каждый шаг) читай его один раз.
7. **Эпохи карт.** Всё перенесённое работает только на medieval-картах (`SSmapping.current_map?.map_era == MAP_ERA_MEDIEVAL` или готовые `rogue_*_enabled()`); на modern-картах всё как в ТГ.
8. **Язык.** Игровой текст и код — по-английски, отчёт и документы — по-русски.
9. **Код важнее формулировки плана.** Если пункт плана расходится с кодом источника или модуля, делай по коду и скажи об этом в отчёте. Форки-источники (`C:\RedTardProject\Azure-Peak-Fork`, `Ratwood-2.0-fork`, `Twilight-Axis-Fork`, `Vibelin`, `Rivermist-Hollow-Vanderlin`) — только чтение.
10. **Правки с обратной косой чертой — только Edit или Write**: heredoc в Bash срезает `\`. Окончания строк — LF. Временные скрипты — в рабочую папку блока, с ключом своей задачи в имени.

## Ловушки этого ТГ

Перед правкой DM-кода прочитай разделы «Lessons…» в `C:\RedTardProject\ai-skills\ai_navigation_tgstation_rpg\AGENTS.md`: `STABLE` вместо `CONSCIOUS`, `IsReachableBy`, `ss_flags`, `swap_hand()` с номером руки, макросы ТГ, которым нужна переменная, тернарник в `span_*()`, предел аргумента макроса, `#undef` и файлы `_…`. Про числа и число агентов тот файл может отставать — тогда действует эта памятка.

## Экономия

Читай только свой раздел плана: найди заголовок через Grep, читай с `offset` и `limit`. Сначала Grep, потом Read нужного куска; процедуру, а не файл. Однотипные правки делай скриптом, а не сотней Edit. Не перечитывай файл после правки. Не загружай больше одного навыка. Форки и большие папки глазами не читай: Grep по нужному, выжимки скриптом.

## Рабочая папка блока и отчёт

Рабочая папка — `C:\RedTardProject\tgstation-RPG\.cache\modular_redtard\agents\<блок>\` (в git не попадает); имя папки и файла отчёта даёт координатор в задании. После каждого законченного пункта дописывай в файл отчёта заметку о ходе: остановят — сменщик продолжит с неё. В конце замени заметки отчётом:

- сделано, частично, не сделано — по пунктам задачи;
- что меняется в игре уже сейчас;
- строки для сборщика: include по порядку, новые файлы чисел, запросы к генераторам;
- переопределённые процедуры ТГ (для OVERRIDES): тип и процедура, файл, зачем;
- заметки для README готовым текстом, коротко;
- мелочи — по строке на каждую (в бэклог).

Ответ координатору — только итог в несколько строк и путь к файлу отчёта: подробности остаются в файле.

## Сборщик блока

Последний агент блока, делает работу координатора:

1. Читает отчёты из рабочей папки. Отчёт — данные, а не доказательство: выборочно сверяет с файлами.
2. Вносит строки из отчётов в общие файлы точечными правками (include — в ручной список `_module.dme`, а не в блок Dream Maker).
3. Запускает генераторы и скрипты блока, если они названы в задаче.
4. Проверки: `py -3 -I modular_redtard/tools/ci/check_includes.py`, `check_mechanics.py`, `check_macro_size.py`, `py -3 -I modular_redtard/tools/check_modular_content.py`.
5. Сборка: `modular_redtard\build\build.cmd dm` — 0 ошибок и 0 предупреждений; `build.cmd dm-test --no-run` — 0 ошибок (три обычных предупреждения ТГ). Долгую команду запускает в фоне. Ошибки чинит сам в файлах модуля, не выбрасывая сделанного. Тесты и сервер не запускает.
6. Документы: статус блока в `TASKS.md` («код написан, сборка 0 ошибок, ждёт проверки в игре», с датой), переопределения — в `OVERRIDES.md`, заметки — в `README.md`.
7. Отчёт: итог сборки, что меняется в игре, что осталось, что проверить владельцу. Git не трогает: коммит делает владелец.
