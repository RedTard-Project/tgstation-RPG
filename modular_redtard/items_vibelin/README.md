# items_vibelin — свои предметы Вайблина

Предметы, которые есть только у Вайблина (ядро Vanderlin и его `code/`), а не у Азура, Ратвуда или Twilight Axis. Гардероб из `modular_abel` — отдельно, в `wardrobe/`.

| Файл | Что это |
|---|---|
| `port.json` | настройки: группы (корни, пропуски с причиной), интенты, навыки, слитки, числа, сброс переменных |
| `selection.tsv` | отбор: какие типы Вайблина его (`pick` = `vibelin`) и почему (`verdict`) |
| `weapons.dm`, `clothing.dm`, `decor.dm` | **генерируются**, руками не править |
| `icons/` | спрайты под путями Вайблина; совпадающие с гардеробом берутся из `wardrobe/icons` |
| `onmob_bake.json` | очередь печи спрайтов в руках, на поясе и на спине |

Перегенерировать (из корня репозитория, Вайблин рядом в `../Vibelin`):

```
py -3 modular_redtard/tools/port_vibelin_items.py
```

`--refresh-selection` заново пишет `selection.tsv` из списков К1в (`.cache/modular_redtard/agents/k1/k1v_lists`) и сверяет пары по имени с путями и спрайтами Азура, Ратвуда и Twilight. Нужны все три форка рядом. То же запускает `port_vibelin.py --items`.

## Куда ложатся вещи

Корень Вайблина → корень модуля того же вида с шагом `vibelin`: `/obj/item/weapon/sword/long/x` → `/obj/item/rogueweapon/sword/vibelin/long/x`, `/obj/item/clothing/head/x` → `/obj/item/clothing/head/roguetown/vibelin/x`. Вещь сохраняет поведение своего вида: ножны, звуки парирования, код оружия модуля. То, что корень модуля задаёт сам, у вещи либо записано, либо сброшено (`resets`). Промежуточные шаги, которых никто не переносит, объявлены абстрактными.

## Как переводятся переменные

- Интенты — интенты модуля (Азура) с тем же путём, псевдоним из `intent_aliases` (`polearm/*` → `spear/*`, `knuckles/*` → `mace/*`, `katana/*` → `sword/*`) или ближайший родитель, который есть в модуле.
- Навыки: `axesmaces` → топоры или булавы по корню вещи; `weapon_repair` → `weaponsmithing`. Переплавка: `melting_material` → слиток модуля.
- Баланс Вайблина (шкала уклонения от −2 до 2) → три ступени модуля (`WBALANCE_HEAVY`, `NORMAL`, `SWIFT`).
- Одежда — по таблице `wardrobe/port.json`. Датум брони, которого нет в карте гардероба, получает тир ближайшего названного родителя, а если такого нет — ближайший по процентам Вайблина.
- Числа (целостность, сила, сила в двух руках, бросок, защита, мин. сила) в типе не пишутся: они идут в приватную `items.txt`. Целостность оружия умножается на 0,42: шкала Вайблина в 2,4 раза больше (медиана пар К2г).
- Пробитие Вайблина (проценты брони) не переносится: пробивают интенты.

## Что не перенесено

Список с причиной даёт `--lists <папка>` (`k3g_skipped.tsv`). Главное: пусковые и патроны Вайблина, еда и посуда (у модуля еда Ратвуда), ключи от дверей его карт, рыболовные снасти, наборы зачарования, органы, материалы его ремёсел, книги и магические предметы.

## Спрайты в руках

Вайблин рисует вещь в руке, на поясе и на спине из её собственного спрайта по `getonmobprop()`. Генератор ставит эти состояния в очередь `onmob_bake.json`. Печь — `ai-skills/scripts/bake_onmob_sheets.py` (собирает и запускает маленький DM-проект). Потом генератор нужно прогнать ещё раз, и он впишет готовые листы. До этого у оружия нет спрайта в руке.
